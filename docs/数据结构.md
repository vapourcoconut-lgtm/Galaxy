# 数据结构设计

## 1. 设计原则

- 单一事实来源：正式数据只保存在数据库。
- 所有业务表包含 `id`、`user_id`、`created_at` 和 `updated_at`。
- 用户只能访问自己的记录。
- 删除优先采用归档，避免误删历史数据。
- AI 输出与原始记录分开保存，便于追溯。
- 未提供的数据使用空值，不使用猜测值。

## 3. 统一任务字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | text | 任务名称 |
| `module` | enum | dashboard / ielts / application / academics / health / reading / personal |
| `goal_id` | uuid | 关联目标，可为空 |
| `objective` | text | 任务目标 |
| `priority` | enum | P1 / P2 / P3 / P4 |
| `due_at` | timestamp | 截止时间，可为空 |
| `estimated_minutes` | integer | 预计时间 |
| `actual_minutes` | integer | 实际时间 |
| `status` | enum | 统一状态 |
| `required_materials` | text | 所需资料 |
| `next_action` | text | 下一步行动 |
| `completion_criteria` | text | 完成标准 |
| `completed_at` | timestamp | 完成时间 |

统一状态：

`待规划`、`待处理`、`进行中`、`等待资料`、`待确认`、`已完成`、`已暂停`、`已取消`

## 4. 雅思公共字段

| 字段 | 说明 |
|---|---|
| `session_date` | 训练日期 |

## 6. AI 分析的可追溯性

每条 AI 分析至少保存：

- 分析类型
- 分析时间范围
- 引用的记录 ID
- 已确认事实
- 分析结论
- 假设
- 建议
- 模型与提示词版本
- 用户是否接受建议

没有足够记录时，分析状态为 `insufficient_data`，界面显示“暂无足够记录”。

## 7. 数据安全

- 开启 Row Level Security。
- 不在前端暴露服务端密钥。
- 申请资料和日记默认私有。
- 文件下载使用短期签名链接。
- 支持用户导出所有个人数据。
- 上线前测试备份恢复，不只测试备份生成。
