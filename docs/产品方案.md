# 个人成长型 AI 工作台产品方案

## 1. 核心结论

推荐使用 **Next.js PWA + Supabase + Vercel** 建设单用户、移动端优先的个人成长工作台。

这套方案适合当前情况：

- 一个固定网址同时支持手机和电脑访问。
- 前端、数据库和身份验证边界清晰，后续可持续扩展。
- 第一阶段可以从低成本配置起步。
- 数据保存在数据库中，不依赖浏览器缓存。
- 后续可增加 AI 周报、趋势分析、文件上传和提醒。
- 可以逐步开发，不需要一开始完成所有模块。

第一阶段只建设真正会高频使用的闭环：

`制定今日计划 -> 执行并记录 -> 晚间复盘 -> 每周分析 -> 调整下周计划`

## 2. 三种技术方案对比

| 方案 | 构成 | 开发难度 | 初期成本 | 优点 | 局限 | 结论 |
|---|---|---:|---:|---|---|---|
| A 快速搭建 | Notion/Airtable 类数据库 + 表单/自动化工具 | 低 | 低至中 | 上线快、无需大量开发 | UI 和分析受平台限制，长期费用与迁移成本可能上升 | 适合短期验证，不作为最终方案 |
| B 长期可扩展 | Next.js PWA + Supabase + Vercel | 中 | 可低成本起步 | 固定 URL、数据库、手机适配、扩展性和维护性平衡 | 需要一次规范开发与部署 | **推荐** |
| C 专业级 App | Flutter/React Native + 独立后端 + 应用商店 | 高 | 中至高 | 原生体验、推送和系统能力强 | 开发、上架和维护明显更复杂 | 当前阶段暂不需要 |

## 3. 推荐技术架构

### 前端

- Next.js App Router
- TypeScript
- Tailwind CSS 或同等轻量样式方案
- PWA Manifest，使手机可“添加到主屏幕”
- 响应式布局，优先适配 375px 至 430px 宽度的手机屏幕
- 图表在第二阶段引入，避免第一阶段复杂化

### 后端与数据库

- Supabase PostgreSQL
- Supabase Auth，用邮箱验证码或 Magic Link 登录
- Row Level Security 限制只有本人能访问个人数据
- Supabase Storage 在后期保存申请材料、作文和论文资料

### 部署

- Vercel 部署前端
- Supabase 托管数据库与身份验证
- 第一版可使用稳定的 `项目名.vercel.app` 地址
- 长期使用建议绑定个人域名，例如 `growth.example.com`
- 后续更新通过同一项目持续部署，访问入口不变

### 数据保存与备份

- 正式数据全部写入 PostgreSQL，不把 `localStorage` 作为主数据源
- 草稿可以临时保存在浏览器，提交后必须进入数据库
- 每月导出一次关键数据为 CSV 或 JSON
- 正式长期使用前确定自动备份、恢复演练和数据导出流程

## 6. 核心交互

### 任务

- 快速添加任务
- 编辑、完成、暂停和取消
- 调整优先级和截止日期
- 查看历史记录
- 未完成任务不自动无限顺延，次日由用户确认重新安排

### 记录

- 每种记录采用短表单，减少管理负担
- 雅思不同科目显示各自字段
- 支持先保存草稿，再补充分析
- 首页提供“快速记录”入口

### 复盘

- 日复盘控制在 5 至 10 分钟
- 周复盘自动汇总数据，用户补充主观判断
- AI 分析只能引用已有记录，并标注事实、分析和建议

## 7. 视觉规范

### 色彩

| 用途 | 色值 |
|---|---|
| 主色、完成状态 | `#A8B5A2` |
| 学习与信息 | `#9AAFC1` |
| 页面背景 | `#F5F1EA` |
| 提醒与日记 | `#C9A7A5` |
| 阅读与长期目标 | `#B8B0C5` |
| 正文 | `#4A4A4A` |

### 设计原则

- 低饱和、清晰、适合长时间使用
- 卡片圆角不超过 8px
- 使用留白和字号建立层级，不依赖装饰
- 避免过多嵌套卡片、渐变、花哨动画和商业后台感
- 交互控件使用熟悉的图标，并提供工具提示
- 首页保持紧凑，手机首屏优先显示行动内容

## 9. 分阶段开发步骤

### 阶段 0：需求确认

- 补充当前雅思水平、考试日期和日常时间边界
- 确认登录邮箱、域名和隐私要求
- 确认第一阶段字段是否足够

### 阶段 1：基础版本

- 建立数据库和权限
- 完成登录、首页、任务、每日计划和复盘
- 完成雅思、运动、阅读记录
- 完成移动端适配、部署和固定网址

验收标准：

- 手机和电脑均可登录
- 新增、修改和完成任务后刷新不丢失
- 所有第一阶段记录可新增、编辑、查询
- 首页只使用数据库中的真实数据

### 阶段 2：分析版本

- 自动生成周报和月报
- 雅思题型、错误类型与时间投入分析
- 习惯趋势图
- 研究生申请管理

### 阶段 3：智能版本

- AI 辅助计划调整
- 作文和口语分析工作流
- 资料检索与引用
- 提醒和更细致的权限、备份与恢复

## 10. 固定访问链接

开发完成后可获得两层固定入口：

1. 免费入口：Vercel 分配的项目域名。
2. 长期入口：绑定个人域名或子域名。

后续每次更新仍部署到同一个项目，网址保持不变。数据库与前端部署分离，更新页面不会删除数据。

本次仍处于产品设计阶段，因此现在不能提供一个已经上线且可实时更新的固定链接。固定链接将在第一阶段 Web App 部署完成后生成。

- 是否需要中英文界面

## 12. 首次启动建议

第一周不要追求完整数据。只执行以下动作：

1. 每天建立三项最高优先级任务。
2. 记录雅思四科实际投入和核心结果。
3. 晚上完成短复盘。
4. 运动和阅读只记录事实，不增加复杂指标。
5. 周末根据七天真实记录调整下一周。

第一阶段的成功标准不是“功能多”，而是连续使用后能够回答：

- 时间实际投入在哪里？
- 雅思主要失分原因是什么？
- 哪些计划经常无法完成？
- 精力、情绪和运动是否影响学习？
- 下一周最值得调整的一件事是什么？
